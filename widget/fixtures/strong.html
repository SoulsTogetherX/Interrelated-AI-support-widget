Acme — signed-in app

A pretend logged-in application page. The support bubble here was opened with a session minted by this site's server, not by a publishable key on the page — view source and find none.

Try it

  1. On the dashboard: create an org, allowlist http://localhost:4400, generate a secret key on the overview.
  2. Run the fixture server with it: INTERRELATED_SECRET_KEY=sk_live_… npm run fixtures
  3. Open the bubble: the widget calls GET /api/support-session here, this server calls POST /v1/sessions there with the secret key, and the token comes back for user_42 — who the dashboard's transcript will name as identified by your server.
  4. Without the key exported, the endpoint answers 503 and the widget says it could not start — what a customer sees with an unconfigured server.
